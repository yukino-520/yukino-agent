# AGI Yukino

AGI Yukino 是一个独立实现的《我的青春恋爱物语果然有问题》侍奉部情感陪伴 Agent。它以雪之下雪乃为核心，同时提供由比滨结衣、比企谷八幡、一色彩羽和平冢静五种陪伴视角。

项目是粉丝向、非官方、个人学习用途。角色风格用于营造陪伴感，不替代现实中的医疗、心理、法律或紧急援助。

## 已有能力

- 五名角色各自独立的私聊、多会话历史与侍奉部会议会话
- 手动/自适应角色路由与群像编排
- 情绪、意图、安全风险和回应质量判断
- PostgreSQL + pgvector 是唯一事实库；Elasticsearch 承担会话隔离的 BM25 与海量文档分块检索，Kafka 通过 transactional outbox 承担多实例事件流；Milvus/Neo4j 是可重建语义与图投影
- 关系状态、心理状态、自我模型、反思与互动学习
- 主动关怀、提醒、行为倾向和上下文检查点
- 时间、记住、回忆、忘记、清空记忆和真正可调度的提醒工具；支持自然语言时间、IANA 时区、每天/每周重复、取消和到期送达
- 原生多步 Agent 循环：模型选择工具、读取真实结果并继续执行，兼容不支持工具调用的模型降级
- 代码语言识别、Python 语法检查、常见安全风险初检和模型语义分析
- 聊天附件闭环：会话隔离上传、哈希完整性校验、代码自动检查、PDF/Office 解析、图片外发前确认和历史回显
- 受控文件工作区、项目只读访问、桌面/自定义目录授权、覆盖与修改确认
- 默认拒绝降级的 Python 系统沙箱、依赖感知工作流与能力搜索；长工作流可在确认后进入持久后台队列，聊天请求立即返回，完成后回写原 Agent 任务账本
- SSRF 防护网页研究、多格式文档阅读、系统状态和素材上传
- MCP HTTP JSON-RPC 与官方 SDK 驱动的本机 stdio、扩展清单、邮件、QQ/微信/Webhook 入站契约；stdio 完成标准初始化/能力协商/关闭生命周期，不经过 Shell，应用密钥仅按服务显式传入且每次启动需确认；MCP `tools/list` 会把限量、去指令化后的工具名与参数注入 Agent 能力目录，远端 annotations 不参与本地授权；外部入站必须通过 HMAC-SHA256、5 分钟时间窗和持久 event_id 防重放校验
- MCP、邮件、媒体、插件和工作流统一接入聊天 Agent；外部副作用统一进入可审计确认队列
- 能力权限策略中心：可全局关闭整项能力或单个动作，并为当前会话发放限时、限次数授权；授权不替代原有风险确认，工作流子步骤也不能绕过
- 工具输出信任边界：网页、文档、文件、MCP、插件和持久记忆正文按不可信数据隔离并记录来源/摘要；模型发起的副作用必须存在于用户本轮执行契约，疑似提示注入会冻结本轮后续副作用
- 确定性步骤已经完成文件、提醒或记忆等副作用后，本轮模型切换为只总结模式；即使供应商返回未提供给它的工具调用或兼容文本工具标记，也不会重复执行。模型整理超时不再否定已经通过指纹/领域证据验收的结果
- PostgreSQL 持久化确认单、工具执行历史和聊天请求幂等，刷新或重启不会丢失待确认操作；同一委托内重复的副作用工具调用会复用原结果或原确认单
- 持久任务账本、步骤状态、结果验收、执行中停止、启动中断恢复和同账本历史委托恢复；恢复不会换任务号，已完成副作用继续复用原证据，不确定副作用必须再次明确授权
- 模型多步循环持久恢复点：每轮保存“等待模型、工具决策、工具结果已提交、回答就绪”等结构边界、参数指纹和步骤引用；不保存模型隐式推理、用户原文或工具正文，恢复时只注入安全证据上下文
- 崩溃窗口副作用对账：显式记忆、提醒、待办使用任务级幂等凭据，首次文件创建使用结构化回执与 SHA-256；重启后能证明已生效的步骤自动认领且不重复执行，能证明未发生的步骤可安全重试，证据冲突则保持人工检查
- 外部副作用使用独立 PostgreSQL 外发账本：确认单先生成稳定 dispatch ID 和供应商幂等键，再调用邮件、MCP、插件、媒体或系统任务；进程在外发后崩溃时只标记“结果待核对”，不会自动重发，用户显式重试仍复用原标识
- 确认后重新验收整份证据契约，不以单个成功操作冒充整单完成
- 按委托生成的执行计划与证据契约：文件、网页、邮件、MCP、媒体和附件缺少真实工具证据时绝不标记完成；失败后取得替代证据可识别为已恢复
- 文件原子写入、SHA-256 落盘校验与限时回滚；确认覆盖后再次核对旧文件指纹，防止确认期间的外部修改被覆盖；固定本机任务支持目录/超时白名单和整组子进程清理
- 任务审计递归脱敏，文件正文、代码、请求头、令牌和密码不重复写入步骤日志
- 每条委托保存独立的时长、模型调用、Token、费用和工具调用预算；并发模型请求先原子预占额度，超时但可能继续计费的请求会记为不确定用量，超限后可提高设置并恢复原任务
- 外部依赖按目标熔断：网页和只读 MCP 有限重试，邮件、插件、MCP 工具调用及媒体生成等副作用绝不自动重试
- 模型并发槽位和可停止等待：停止委托后立即结束当前等待，仍在供应商侧运行的请求受并发上限约束
- 主模型按超时、认证、限流、网络、服务端和空响应分类记账；连续失败自动熔断，冷却后单探针恢复，尚未执行工具时可切换已配置的备用模型，执行过工具后禁止整轮重放
- 提醒使用 PostgreSQL 状态机和领取租约：刷新或重启不丢失，多标签页不会重复领取；设置 Webhook 并开启后台派送后，页面关闭仍可送达
- 后台作业使用 PostgreSQL 租约、退避重试、停止和死信状态；服务重启会接续安全作业，不确定的工作流副作用不会自动重放
- 网页聊天也使用独立的持久 Agent 工作池：不同会话可并行执行，同一会话严格按提交顺序串行；容量与单会话上限提供原子背压，提交立即返回作业号，刷新或暂时断网可恢复状态，停止会同时作用于作业、任务和后续工具
- 规划、上下文准备、模型请求/切换、工具开始/完成、等待确认、验收和停止会写入脱敏的 PostgreSQL 事件账本，并经 transactional outbox 投递 Kafka；Kafka 唤醒各实例 WebSocket，断线或漏通知时由数据库游标补偿
- Agent 运行租约由心跳持续续期；服务重启会立即回收孤儿租约，取消状态不能被迟到的模型结果覆盖；保存运行设置时会等待当前轮次结束并原子切换模型、工具和检索实例
- OpenAI-compatible 主模型、备用模型和无密钥降级回复
- 原生 FastAPI/WebSocket API、终端聊天和专属 Web 活动室/部务台
- 运行追踪、doctor 检查和可撤回学习数据

## 启动

```bash
cd agi-yukino
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env  # 已有 .env 时不要覆盖
docker compose -f docker-compose.storage.yml up -d
agi-yukino serve
```

本机存储状态可用 `agi-yukino storage status --json` 检查。`YUKINO_DATABASE_URL`、`YUKINO_ELASTICSEARCH_URL` 和 `YUKINO_KAFKA_BOOTSTRAP_SERVERS` 为生产数据面配置；缺少 PostgreSQL 会直接拒绝启动。具体边界、旧库导入和索引重建命令见 [存储架构](docs/STORAGE_ARCHITECTURE.md)。

浏览器打开 `http://127.0.0.1:8082`。没有配置 `OPENAI_API_KEY` 也能启动，聊天会使用每个角色自己的本地降级回应。

在页面“设置 → Agent 与文件”中可以开启多步执行、调整最多工具步骤、并行工作线程、队列总容量和单会话等待上限，并授权桌面或其他输出目录。相对路径默认写入 `data/workspace`；项目源码默认只读；覆盖和修改已有文件必须在聊天里再次确认。密钥、凭据和 Git 内部文件始终禁止访问。

在“设置 → 能力权限”中可以关闭 Python、网页、文件、系统任务、MCP、插件、邮件、媒体等整项能力或单个动作。策略默认允许以兼容现有行为；显式关闭后，只有绑定当前会话、带到期时间和剩余次数的临时授权能够放行。次数在真正执行前通过 PostgreSQL 写事务原子扣减，并发请求不会共同消费同一次授权；预检和等待确认不会扣次数。临时授权不替代 `confirmed` 风险确认，会话清理或删除时一并撤销。同步、后台工作流的每个子步骤都会重新通过同一闸门。

在“设置 → MCP 连接”可同时配置远程 HTTP JSON-RPC 和本机 stdio 服务。stdio 的 `command` 与 `args` 必须分开填写，`cwd` 只能是绝对路径，Agent 不调用 Shell；SDK 仅继承运行所需的 `HOME/LOGNAME/PATH/SHELL/TERM/USER`，API Key 等应用环境不会自动传入。服务自己的 Token 放入单独的“stdio 专用环境变量”字段，该字段按秘密配置保存且 API 只返回变量名。发现工具也会启动本机程序，因此每次都走与调用工具相同的确认门禁、超时/停止和子进程清理。

Python 小实验默认使用 `YUKINO_PYTHON_SANDBOX_MODE=strict`。在 macOS 上，代码先经过 AST 与对象属性白名单，再进入 `sandbox-exec` 的拒绝优先系统策略，只允许读取 Python 运行库；用户目录/工作区读写、网络连接和其他进程启动均被内核策略拒绝，同时设置 CPU、内存、文件描述符、进程数和输出上限。系统后端不可用时会直接拒绝执行，不会悄悄退回普通子进程。`language` 模式只用于受约束的开发/CI，Doctor 与设置页会明确标为降级，不能视为安全沙箱。

代码分析先由本地确定性检查提供语言、语法、结构和已知风险证据，再交给模型做语义审查。若模型超时或暂时不可用，降级回复会把这些证据整理成“概况、确定问题、修改建议和能力边界”，不会再把内部 JSON 原样贴给用户，也不会把本地静态检查冒充成完整业务语义分析。

网页、文档、本地文件、MCP/插件返回值和自动召回的记忆不会再作为普通内部指令拼入 Prompt，而会装入带来源与 SHA-256 的 `UNTRUSTED_TOOL_OUTPUT` 数据边界；双向控制符、零宽字符会先移除，传给模型的单项正文有长度上限。模型只能读取这些资料，不能从中取得新的写文件、记忆、提醒、待办或外部操作授权。所有模型发起的副作用都会与用户原话生成的执行契约核对；命中“忽略系统规则、泄露密钥、伪造用户授权、立即调用工具”等注入信号时，本轮后续副作用全部阻止，用户需在新消息中重新明确委托。任务事件、`/api/status` 与 Doctor 只展示信任等级、来源、信号和摘要，不保存外部正文。

固定检查可以在同一设置页配置成结构化任务，例如 `{"lint":{"command":[".venv/bin/python","-m","ruff","check","service_club"],"cwd":"project","timeout_seconds":120,"description":"检查项目源码"}}`。`cwd` 只允许内部 `workspace` 或项目 `project`，也兼容旧的参数数组格式；命令不经过 Shell，Agent 不能临时拼接任意终端命令。每次执行前，任务的命令、目录和超时都会生成非秘密目标指纹并写入持久确认单；确认期间若设置被修改，旧确认会失效。停止和超时会结束整个子进程组。服务意外退出时，运行中的任务会标记为“服务中断”而不会自动重放，页面允许先把原委托恢复到输入框检查后重新发送。

每次工具型委托都会先生成持久化执行计划和必要证据清单。页面任务卡会显示计划与证据状态；如果模型只声称“已经完成”却没有对应的文件校验、网页结果或外部能力回执，任务会明确标记为验收失败。点击“恢复这条委托”会同时恢复仍然存在的会话附件。

页面任务卡同时显示最近的结构恢复点编号、状态和模型轮次。它不是模型“思维过程”存档：PostgreSQL 只保存消息上下文 SHA-256、工具参数 SHA-256、工具名、步骤号和执行状态。恢复后模型会收到这些持久证据与防重放规则，已经完成的写文件、提醒等副作用不会因为重新推理而自行再做一次。

确认后的外部动作会先写入 `agent_external_dispatches`。HTTP MCP/插件/媒体请求携带稳定的 `Idempotency-Key` 与 `X-AGI-Dispatch-ID`，MCP JSON-RPC 同时使用稳定请求 ID，邮件使用稳定 `Message-ID`；回执只保留响应指纹和允许列出的供应商编号，不保存正文或密钥。若服务在供应商调用开始后失去终态，页面显示“外发结果待核对”且禁止自动重放；若完成回执已经落盘但本地确认单尚未提交，重启会自动认领确定结果。可在“设置 → 外发记录”按当前会话查看记录，并选择“确认外部已成功”“使用原标识重试”或“放弃本次外发”。三个动作都使用条件事务防并发双击。这里不能凭空保证第三方 exactly-once：只有供应商真正遵守幂等键时才能去重，因此显式重试前仍应先检查对方系统。

委托执行期间，待处理消息中的“执行过程”会实时显示任务当前阶段和脱敏事件。事件以单调递增游标保存在 PostgreSQL；WebSocket 负责低延迟推送，原有作业轮询负责断线补偿，因此临时断网、切换会话或刷新页面不会让过程记录消失。事件接口和订阅都校验 `session_id`，不会读取其他会话的任务。

“Agent 与文件权限”设置页可调整新任务的资源预算。费用闸门只有在填写模型输入/输出单价后启用，因为 OpenAI-compatible 服务没有统一价格；任务会保存创建时的单价和限额快照。恢复任务会保留已用额度，只接受提高后的上限，不会借恢复来降低旧任务约束或重置用量。

模型最大并发、熔断阈值和冷却时间可在“设置 → 模型与 API”调整，主模型与备用模型可以分别发起真实连接探测；探测与聊天共用同一套超时、并发和健康状态机制。网页抓取和只读 MCP 遇到 408、429 或临时 5xx 时采用短退避重试；所有外部目标分别维护熔断状态，可通过 `/api/status`、`/api/doctor` 或“运行观测”能力检查。

网页研究继续阻止直接访问私网、保留地址和内部域名。若系统代理使用 `198.18.0.0/15` Fake-IP DNS，运行时会通过公共探测域自动识别并保留域名级校验；可在 `.env` 中设置 `YUKINO_ALLOW_FAKE_IP_DNS=false` 强制关闭兼容。

QQ、微信和通用 Webhook 的入站密钥可在“设置 → 通道与邮件”保存。外部请求需要同时提供 `X-AGI-Yukino-Timestamp`、`X-AGI-Yukino-Event-Id` 和 `X-AGI-Yukino-Signature`；签名值为 `sha256=HMAC_SHA256(secret, timestamp + "." + raw_body)`。时间戳允许 5 分钟误差，同一通道的 event ID 只会执行一次。网页聊天不经过这个外部通道入口。

聊天输入框的“添加附件”支持最多 4 个代码、UTF-8 文本、PDF、DOCX、XLSX、PPTX 或常见图片，单个文件最大 10 MiB（代码和文本最大 2 MiB）。附件只能被所属会话引用；代码和文档在本地受控工作区读取，图片视觉分析会先显示确认按钮，确认后才会发送到已配置的模型。

终端聊天和运行检查：

```bash
agi-yukino chat --character yukino
agi-yukino chat --club
agi-yukino doctor
```
